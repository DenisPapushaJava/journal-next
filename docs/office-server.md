# Сервер программы «Заявки»

Рабочий Windows-компьютер хранит общую MDB и папку проектов. Сервер обращается к MDB через существующий AccessHost x86 и отдаёт клиенту данные через API. На домашнем компьютере CAM и Word будут работать с локальной копией выбранного проекта.

## Репозиторий и сборка

Сервер и окно управления находятся в репозитории `journal-next` отдельными проектами `Jornal.Workflow.Server` и `Jornal.Workflow.Server.Windows`. Общие модели MDB и AccessHost остаются там же, поэтому совместимость можно проверять при изменении схемы. Настольное приложение и сервер зависят от этой общей части независимо. Сервер собирается по своему `.csproj` вне настольного решения `Journal.Next.slnx`. Для будущих выпусков сервера предусмотрим отдельную сборку и отдельные пакеты. Установщик и канал обновлений «Заявок» предназначены для настольной программы.

## Первый этап

Локальный API ASP.NET Core слушает `127.0.0.1`. При включении удалённого доступа открывается тот же API на проверенном приватном IPv4-адресе ZeroTier. При ручном запуске порт по умолчанию — 5197. При установке через окно управления выбирается свободный локальный порт. Доступ к рабочим данным требует случайного ключа.

| Запрос | Результат |
| --- | --- |
| `GET /health` | `200`, если HTTP-сервер запущен. |
| `GET /api/v1/status` | Проверяет подключение к MDB и наличие рабочей папки. `503`, если один из ресурсов недоступен. |
| `GET /api/v1/orders` | До 20 последних активных заявок, общий счётчик и версия снимка. В ответе только ID, номер, заказчик, версия заявки и время изменения. |
| `GET /api/v1/diagnostics` | Версия и идентификатор сборки, время запуска, до 64 последних ошибок чтения MDB и работы с тестовыми файлами. |

У операций `/api/v1` один ключ. AccessHost читает общие поля заявок и заказчиков из MDB «Заявок» схем 1–7. Версия базы видна в поле `schemaVersion` ответа `/api/v1/status`. Чтение работает без изменения схемы. Ошибка чтения возвращает код состояния, подробности доступны в журнале сервера. При изменении снимка во время чтения списка сервер возвращает `409`. Проверка папки сообщает, видна ли она серверу.

## Пробный запуск на Windows x64

1. Запустите `JournalOfficeServer-Setup-win-x64-v19.exe` под тем пользователем Windows, под которым будет работать сервер. Установка доступна через «Пуск → Сервер заявок», удаление — через «Установленные приложения».
2. Укажите тестовую MDB и папку проектов. Кнопка **«Создать тестовую MDB»** подготовит пустую базу и папку в профиле пользователя.
3. Нажмите **«Сохранить и запустить»**. Панель проверит доступ к MDB и папке. По умолчанию удалённые пользователи могут читать заявки и скачивать файлы. Для проверки записи на тестовой MDB включите **«Разрешить удалённое сохранение»** и примените настройку. Если включён автозапуск, после входа под этим же пользователем сервер стартует, а панель появится в трее.
4. В ZeroTier Central создайте отдельную **приватную** сеть для теста и скопируйте её **Network ID**. Оставьте автоназначение IPv4. Диапазон должен отличаться от подсетей офиса и дома. [Создание сети ZeroTier](https://docs.zerotier.com/start/)
5. При необходимости нажмите **«Установить ZeroTier»** и подтвердите установку в Windows. Панель скачивает официальный MSI 1.16.2 и проверяет SHA‑256 по манифесту WinGet.
6. Вставьте **Network ID** в панели и нажмите **«Подключить»**. Разрешите появившееся устройство в ZeroTier Central. Панель ждёт подтверждения до двух минут. Если потребовалось больше времени, повторное нажатие «Подключить» продолжит настройку существующего подключения.
7. Подтвердите настройку порта в запросе Windows. Панель создаёт правило только для приложения, порта и адаптера ZeroTier. После запуска слушателя кнопка **«Копировать адрес»** отдаёт приватный адрес. Для отладки используйте **«Ключ администратора»**, для рабочих операций — ключ выбранного сотрудника в **«Доступ технологов…»**.

Для обновления запустите новый установщик. Он подготавливает файлы, штатно останавливает сервер и возвращает его в работу, если тот был запущен. Если новая версия не восстановит доступ к MDB или порту ZeroTier, работавшему до обновления, установщик вернёт предыдущую версию. Пути, ключи и параметры ZeroTier сохраняются. При переходе с архивного прототипа закройте его окно перед обновлением.

### Запуск при входе в Windows

В панели включите **«Запускать при входе в Windows»** и нажмите **«Сохранить и запустить»**. После перезагрузки войдите под этой же учётной записью Windows локально или через AnyDesk. Сервер запустится в фоне и сам откроет сохранённый порт после подключения ZeroTier. Блокировка экрана сохраняет сеанс и доступ. При переходе с v16, если был включён запуск до входа, подтвердите запрос Windows на удаление старой задачи. Установщик перенесёт настройку в обычную автозагрузку.

Для проверки перезагрузите Windows, войдите в свою учётную запись и обновите список заявок с другого устройства. Откройте файл проекта, чтобы проверить доступ к рабочей папке.

Если сеть временно пропала, сервер снова откроет доступ, когда вернётся настроенный адрес ZeroTier. После прерванного сохранения нажмите F5 и проверьте состояние записи перед повтором.

На втором компьютере установите ZeroTier, присоединитесь к тому же **Network ID** и подтвердите второе устройство в ZeroTier Central. [Установка ZeroTier](https://www.zerotier.com/download/)

На втором компьютере откройте приватный адрес с добавленным `/health`. Если виден ответ `{"status":"ok"}`, соединение дошло до нашего сервера. Чтобы проверить чтение заявок в PowerShell, выполните:

```powershell
$officeAddress = (Read-Host 'Приватный адрес сервера').TrimEnd('/')
$officeKey = Read-Host 'Ключ API' -AsSecureString
$officeHeaders = @{ Authorization = 'Bearer ' + [System.Net.NetworkCredential]::new('', $officeKey).Password }
Invoke-RestMethod "$officeAddress/api/v1/status" -Headers $officeHeaders
Invoke-RestMethod "$officeAddress/api/v1/orders" -Headers $officeHeaders
Remove-Variable officeHeaders, officeKey
```

В Linux подойдёт Bash с curl:

```bash
read -r -p 'Приватный адрес сервера: ' office_address
read -r -s -p 'Ключ API: ' office_key
printf '\n'
printf 'header = "Authorization: Bearer %s"\n' "$office_key" | curl -fsS --config - "${office_address%/}/api/v1/orders"
unset office_key
```

Успешный ответ для новой тестовой MDB содержит `totalCount: 0`. Если нужно проверить непустой список, создайте заявку через настольную программу, подключённую к этой тестовой базе, и повторите запрос.

Для удалённой диагностики с версии v7 используйте тот же ключ и запрос `GET /api/v1/diagnostics`. Скрипт `check-office-file-pilot.py` делает такой запрос с параметром `--diagnostics`. В удалённом журнале доступны время, этап, тип исключения и числовой код ошибки. Журнал хранится в памяти текущего процесса. Полные сообщения и стеки остаются в «Журнале» на серверном ПК.

Сверните окно или нажмите крестик, чтобы убрать окно с панели задач. Двойное нажатие по значку в трее открывает панель. В меню значка доступны запуск, остановка и открытие журнала. **«Закрыть панель»** убирает значок, а сервер продолжает работать. **«Отключить доступ»** закрывает слушатель ZeroTier. Если приватный IPv4-адрес или адаптер изменился, отключите доступ и подключитесь снова.

«Журнал» открывает текущий `server.log` в `%LOCALAPPDATA%\JournalWorkflowOfficeServer`. Рядом хранятся три предыдущих файла. Удаление через «Установленные приложения» находит именно установленный экземпляр, останавливает сервер и панель, убирает ключи и настройки, журнал, автозапуск и созданное приложением правило брандмауэра. На последнем шаге Windows может запросить права для очистки правила. Рабочие файлы, тестовая MDB, ZeroTier и членство в его сетях сохраняются.

Сборка архива из корня репозитория:

```sh
python3 scripts/build-office-server-setup.py
```

Windows-комплект включает среды .NET для панели x64 и AccessHost x86. Для сборки нужен `makensis`. Готовый EXE создаётся в `.local`. Остальные диагностические примеры ниже относятся к отдельному архиву, который собирается через `build-office-server-trial.py`. [Настройки клиента ZeroTier](https://docs.zerotier.com/config/) · [Правила доступа ZeroTier](https://docs.zerotier.com/rules/)

## Пробный обмен файлами

В тестовой заявке создайте один проект в папке, доступной серверу. Откройте папку проекта из «Заявок» и сохраните в ней через Блокнот `office-pilot.txt` с короткой строкой обычного текста. Используйте UTF-8. Укажите в сервере ту же MDB и корневую папку проектов. По наличию файла сервер определяет проект, подготовленный для проверки. Для остановки обмена этим файлом удалите либо переименуйте его вручную.

С другого компьютера выполните команду с адресом из панели сервера и введите ключ в скрытом приглашении. Скрипт предложит выбрать номер тестовой заявки, затем скачает файл, вернёт правку, проверит отказ для старой версии и прервёт одну загрузку перед её завершением. Локальные копии остаются в папке, которую выведет скрипт.

```sh
python3 scripts/check-office-file-pilot.py http://10.0.0.1:5197/
```

| Запрос | Результат |
| --- | --- |
| `GET /api/v1/orders/{orderId}/file-pilot` | Проекты с тестовым файлом. |
| `GET /api/v1/orders/{orderId}/file-pilot/{projectId}` | Содержимое `office-pilot.txt` и его версия в `ETag`. |
| `PUT /api/v1/orders/{orderId}/file-pilot/{projectId}` | Заменяет тестовый файл после получения полного тела запроса. Нужны `If-Match` с полученной версией и `Content-Length` до 1 МиБ. Успех — `204`, другая версия файла — `412`. |

Источником пути служит MDB. Обмен ограничен обычным файлом `office-pilot.txt` в папке активного проекта под настроенным корнем. При конфликте сохраняются серверный файл и локальная копия. После потери ответа в конце передачи можно скачать файл и проверить, какая версия сохранилась.

## Пробный перенос заявки

Для испытания используется одна пустая заявка, уже созданная на клиенте. Сборка `python3 scripts/build-office-server-trial.py --order-draft /путь/к/заявке.json` включает проверку контрольной суммы её JSON. Сервер принимает этот файл с ключом API через `POST /api/v1/order-pilot`. Обычная сборка оставляет маршрут выключенным. На сервере используется существующий действующий технолог с соответствующим именем и стандартная транзакция создания заявки в MDB. Повторная передача уже сохранённого ID возвращает номер существующей заявки. Текущая запись при этом сохраняется.

На клиенте используйте `check-office-file-pilot.py` с параметром `--draft /путь/к/заявке.json` и приватным адресом сервера. Скрипт подтверждает результат чтением списка. На Windows заявку можно найти по полученному номеру после обновления списка (`F5`).

## Работа с заявками и проектами

В настольных «Заявках» откройте **«Настройки → Хранилище → Подключиться к серверу…»**. При первом подключении возьмите три значения из панели «Сервер заявок» на рабочем ПК. Адрес копируется кнопкой **«Копировать адрес»**, ID офисной сети указан в поле **Network ID**, ключ копируется кнопкой **«Ключ администратора»**. После успешного чтения откроется журнал с офисной MDB. При необходимости выберите технолога в **«Настройки → Общие»**. Для смены источника используйте **«Вернуться к локальной базе»** и **«Переключиться на сервер»** в «Хранилище». Адрес и ключ можно изменить через **«Настроить подключение…»**.

В Linux мастер проверяет уже настроенное подключение ZeroTier по тому же ID сети. Для этой проверки права администратора не нужны при стандартной установке ZeroTier. Первое вступление компьютера в сеть выполняется в ZeroTier.

Если на Windows ещё нет ZeroTier, нажмите **«Скачать ZeroTier»** в мастере и установите программу с официальной страницы. Вернитесь в мастер и нажмите **«Проверить установку»**. Если мастер был закрыт, откройте его снова. Адрес и ID сети сохраняются локально для продолжения.

После установки или если ZeroTier уже есть, «Заявки» отправят запрос на вступление в офисную сеть. Если требуется подтверждение, нажмите **«Скопировать ID устройства»** и передайте ID администратору для авторизации в ZeroTier Central. После подтверждения «Заявки» дождутся настройки адаптера и проверят маршрут и ответ сервера. Источник журнала меняется после успешного чтения заявок. Мастер совместим с сервером v19.

При вступлении через мастер ZeroTier получает управляемые адреса и маршруты после проверки конфигурации сети. Допустимы прямые маршруты внутри подсетей назначенных адресов. Если настройка была прервана, мастер может предложить **«Разрешить адреса»** после проверки. При первом подключении и загрузке заявок окно можно закрыть до сохранения источника журнала.

«Заявки» запоминают проверенный адаптер ZeroTier для повторного входа. Для старого подключения без сохранённого адаптера один раз откройте **«Настроить подключение…»** и подтвердите сеть. Если сохранённый токен ещё действует, поле ключа можно оставить пустым.

`POST /api/v1/storage-connect` выдаёт токен на 30 дней для конкретной MDB. Основной журнал читает и сохраняет записи через `POST /api/v1/storage/database`. Сервер определяет физический путь сам. Поддерживаются схемы 6 и 7 без миграции при удалённом подключении. Для записи нужна настройка **«Разрешить удалённое сохранение»**.

Кнопка открытия проекта скачивает локальную копию из серверной папки. **«Папка для локальных копий»** задаёт путь для новых скачиваний на этом компьютере. Пустое поле означает папку профиля программы. Новые копии повторяют сохранённую в MDB иерархию `год/месяц/день/заявка/проект`. При повторном открытии программа проверяет содержимое офисной папки и обновляет файлы, которые дома не менялись. Удалённые в офисе файлы убираются из рабочей папки с сохранением копии в `.office-sync`. При правке с обеих сторон можно сравнить версии и выбрать, с какой продолжить.

Отметка **«Есть неотправленные файлы»** отражает локальные добавления и правки. Она проверяется при открытии заявки, возвращении в окно и после отправки. В меню проекта **«Отправить изменённые файлы…»** публикует добавленные и изменённые файлы с проверкой версий. Локальные удаления через эту команду не передаются.

Для удалённого расчёта из обновлённых «Заявок» нужен сервер v19. Нажмите **«Добавить проект»**, затем откройте его папку, подготовьте HTML или PDF-спецификацию и нажмите **«Рассчитать»**. Если локальной копии ещё нет, для расчёта скачиваются только спецификации. Открытие папки проекта догружает остальные рабочие файлы и сохраняет локальные правки.

При принятии выбранная спецификация передаётся с проверкой исходной версии. Сервер сохраняет архив и предыдущий расчёт, затем проверяет рабочую спецификацию при записи в MDB. Если файл изменили и дома, и в офисе, кнопка **«Сравнить версии»** скачивает обе копии и позволяет выбрать, по какой пересчитать. Если файл снова изменился после скачивания, потребуется открыть сравнение ещё раз. Для файлов программы станка и других рабочих файлов используйте **«Отправить изменённые файлы…»**. Историю и передачу в цех можно открыть в офисном режиме.

`GET /api/v1/storage/capabilities` сообщает о поддержке `guardedCalculation`. `POST /api/v1/storage/orders/{orderId}/projects/prepare` подготавливает заготовку по стабильному ID запроса. Для списка спецификаций `GET .../files?reportProfile=...` возвращает доступные файлы и отдельно имена недоступных в `unavailableFiles`. Необязательный `reportName` сужает проверку до выбранного файла. `POST /api/v1/storage/orders/{orderId}/projects/{projectId}/calculation` подготавливает архив и возвращает серверные пути. Условный `Apply` принимает `officeReportVersions` в запросе записи расчёта и проверяет рабочие файлы перед записью через AccessHost.

### Отдельный консольный клиент с личными ключами

В панели Windows откройте **«Доступ технологов…»**. Выберите действующего сотрудника из подключённой MDB, нажмите **«Выдать ключ»**, затем **«Скопировать»** и **«Сохранить»**. У каждого технолога свой ключ. Один сотрудник может использовать свой ключ на нескольких компьютерах. При смене фамилии доступ сохраняется по ID сотрудника. Удалённую работу сотрудника можно отключить кнопкой **«Отозвать»**. Новый набор ключей применяется при перезапуске сервера после сохранения.

Технологи читают заявки и проекты. Создание заявки записывает автора по ключу. Редактирование реквизитов и публикация файлов доступны назначенному технологу. Ключ администратора открывает диагностику и пробные операции. Для рабочих команд нужен ключ сотрудника.

Для первого запуска используйте Python 3.10 или новее и скрипт `client/office-work.py` из папки установки `app`. Команды принимают ваш приватный адрес из панели. `list` показывает номера и ID заявок, `order` показывает реквизиты и ID проектов.

```sh
python3 client/office-work.py "$office_address" list
python3 client/office-work.py "$office_address" order "$order_id"
python3 client/office-work.py "$office_address" new --manager "Фамилия" --customer "Заказчик" --draft ./order-draft.json
python3 client/office-work.py "$office_address" download "$order_id" "$project_id" ./project-copy
python3 client/office-work.py "$office_address" publish ./project-copy
```

Для заранее подготовленной заявки используйте `send-order ./order-draft.json`. `edit` обновляет менеджера и БЛЦБ по версии заявки. После записи обновите список в «Заявках» на Windows клавишей `F5`.

Скачивание сохраняет рабочую структуру проекта, включая пустые папки и «ГИБКА». Откройте файлы в локальной копии. Перед отправкой закройте изменённые файлы в редакторах. Команда `publish` передаёт добавленные и изменённые файлы. Удаление и переименование серверных файлов выполняются отдельно в рабочей папке. Версии проверяются перед началом отправки и перед каждой записью. Если разные файлы отправились с разным результатом, клиент покажет подтверждённые и остановится на первой проблеме. Повторный запуск проверит уже сохранённые файлы.

Предыдущие версии заменённых файлов хранятся в служебной папке `.office-sync` в рабочем проекте. При одновременной замене файла другой программой сервер сохраняет обе версии и выдаёт путь к копии для проверки. «Задание в цех» выполняется из «Заявок» через настроенную папку Яндекс Диска на компьютере технолога.
