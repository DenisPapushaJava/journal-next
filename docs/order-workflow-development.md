27.10.2026 новый локальный этап — автообновление списка общей MDB.
Переключатель в Общих, по умолчанию ON, в локальном preferences.json;
новых таблиц/колонок/версий протокола нет. Наблюдение только за выбранным
MDB, без обхода папок проектов: Changed объединяются и проверяют revision;
замена/появление/удаление файла и восстановление наблюдения требуют сверки

каждые 5 минут. Один фоновый запрос и одна попытка подписки на окно,
повтор подписки после ошибки, увеличение пауз при отказе; скрытое окно
не читает БД. Видимое неактивное окно продолжает обновляться.

WorkflowMdbStore.Background читает только существующие ReadRevision/Read,
используя временный cache/catalogue/cursor. Состояние живого store принимается
отдельно после проверок источника, фильтра/retain ID, отсутствия foreground
записи и исходного снимка. Foreground отменяет чтение до ожидания gate;
поздние ответы после поиска/переключения БД/отключения/закрытия отбрасываются.
Полный диапазон перечитывается до прежнего курсора, страницы должны иметь
одинаковую revision. Неподтверждённый результат записи не снимается фоном.
Read не выполняет Inspect/DDL; миграции и восстановление unknown — явные.

Baseline списка хранится отдельно от версии последнего частичного write/
ReadMore: собственное сохранение не маскирует параллельную правку коллеги.
Неизменившиеся строки после native JSON roundtrip сохраняют свои объекты.

якорем прокрутки и выбором ID. Ввод, проект и письмо не теряются. Чистая
изменившаяся карточка обновляется, грязная остаётся с исходной версией и
предупреждением; запись по устаревшей версии запрещена. «Обновить карточку…»
подтверждает отмену параметров, письмо сохраняется. Сетевой отказ оставляет
данные и компактное сообщение под поиском; без модалок/повтора записей.

## База с прежними ценами

- Лазер/Плазма/Газо-кислородная используют прежние прайсы; HansLaser сохраняет
  базовую категорию, ID 1 и ID 2 отдельно. Добавленные JournalMachines также
  загружаются со своими именами/профилями. PriceLM500 и неиспользуемый PriceHL
  не переносятся.
- Первая строка прайса, дробные толщины и настоящий нулевой тариф сохраняются.
  NULL и пустые таблицы не становятся нулём. Отрицательная цена или ошибка
  чтения останавливает весь импорт без частичного применения.
- Переносятся цены **за метр**. По уточнению пользователя для новых тарифов
  цена пробивки по умолчанию **1 ₽**, далее её можно изменить, в том числе на 0.
  При последующих загрузках уже заданные цены пробивок сохраняются.
- Ранее импортированный тариф, который исчез/стал пустым в источнике, удаляется
  из текущего локального прайса. Тарифы ручных станков вне импорта остаются.
  Версии расчётов сохраняют собственные цены и не пересчитываются автоматически.
- Станок/категория/толщина предлагают загруженные варианты. Для новой
  спецификации подходящий тариф подставляется при изменении ключа. У уже
  сохранённой версии замена цены явная — «Обновить тариф». Ручной ввод остаётся.
  AWJC сопоставляется с единственным станком подходящего профиля; неоднозначный
  станок нужно выбрать вручную, подтверждение материала по-прежнему обязательно.

Источник и время загрузки сохраняются только в собственном workspace Workflow.
При запуске используется последний локальный каталог; запросов к MDB на каждое
изменение поля или фоновую перезагрузку нет. Для новых цен повторить «Проверить →
Загрузить цены». Незавершённый ввод в открытой заявке при этом сохраняется.

используют прежние адаптеры, не общую транзакцию снимка всей MDB.

## Редактирование станков и тарифов

**Верхняя кнопка «Станки и цены»**. Слева выбрать станок; справа изменить имя или
формат импорта. Для тарифа выбрать строку и править поля под таблицей.
«Добавить толщину» создаёт строку с ценой пробивки 1 ₽. «Убрать тариф» убирает
строку из текущего прайса; исторические расчёты остаются. Все изменения
применяются одной кнопкой «Сохранить»; «Отмена» закрывает без записи. Можно
добавлять станки. Удаления станков пока нет, чтобы не терять ссылки.

Станок имеет постоянный UUID. Тариф и параметры спецификации связаны по
MachineId; Name — отображаемое название. Сохранённые версии содержат снимок
прежнего названия и цены. Переименование обновляет подписи открытой формы без
изменения суммы/dirty-состояния и не создаёт версию расчёта. Следующая осознанная
правка спецификации сохраняется уже с текущим названием. Повторный импорт
находит станок по LegacyKey (`legacy:…`/`table:…`), сохраняя локальное имя и
настроенный профиль импорта. Название не является внешним ключом.

Уникальность названий проверяется без учёта регистра. В рамках одного ID
станка и категории материала толщина не повторяется. Толщина положительна,
цены неотрицательны, пробивка задана явно. Проверка и сохранение всего
каталога атомарны под прежней локальной блокировкой/версией; окно редактирования
не держит файл открытым. При конфликте введённые изменения остаются в окне.
Неизменённые данные не записываются повторно. Перед изменением каталога
сохраняется резервная копия собственного workspace.

Локальная схема теперь **2**. При первом чтении схемы 1 создаётся `.bak`,
затем однократно назначаются ID во всех тарифах/версиях спецификаций. Даты,
номера, суммы, авторы и данные заявок не меняются. Следующее чтение использует
те же ID; ошибка миграции не подменяет файл пустым журналом.

На этой машине подготовлен `/home/denis/.config/JournalWorkflow/development-workspace.json`:
149 тарифов из `/home/denis/Myprojects/OrderDB.mdb`, все текущие цены пробивок
установлены в 1 ₽. Имеющаяся заявка/история сохранены; исходный MDB побайтно
не изменился. Две резервные копии лежат рядом с workspace. Это локальное
хранилище разработки; решение об общей сетевой СУБД ещё не принято.

Для повторяемой подготовки отдельной копии есть утилита (последнее число
явно заменяет цены пробивок всех текущих тарифов; не запускать вместо обычного
обновления цен):

```bash
dotnet run --project tools/Jornal.Workflow.Tools -c Release -- prepare-prices /path/old.mdb /path/workflow.json 1
```
