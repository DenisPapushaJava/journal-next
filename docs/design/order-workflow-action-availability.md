# Доступность действий главного экрана

30.10.2026. Правило пользователя: если для действия не хватает данных,
кнопка и соответствующий пункт меню должны быть недоступны. Причина видна
в подсказке, без необходимости нажать и получить ошибку.

## Условия

| Действие | Когда доступно |
| --- | --- |
| Новая заявка | Подтверждён рабочий профиль, программа свободна, новая форма ещё не открыта |
| Создать заявку | Есть профиль, менеджер и заказчик |
| Сохранить реквизиты | Есть изменения, менеджер/ответственный/автор; карточка актуальна |
| Добавить проект | Актуальная карточка без несохранённых правок/незавершённого переименования; есть станок |
| Создать проект | Выбраны станок, положительная толщина и папка проектов; есть автор |
| Загрузить спецификации | Есть активный проект и автор, карточка актуальна, нет несохранённых правок/переименования |
| Сохранить расчёт | Он изменён и рассчитан, проверен материал, есть номер/правильная дата/автор; карточка актуальна |
| Отменить расчёт | Есть несохранённые правки выбранного расчёта |
| Обновить цены | В загруженном каталоге есть тариф для текущего станка/категории/толщины |
| Сформировать результат | Сохранены расчёты включённых позиций, выбран актуальный вариант, нет незавершённых правок/переименования |
| Открыть результат | Уже есть текст либо возможно его формирование |
| Копировать/очистить результат | Есть соответствующий текст, другая операция копирования не выполняется |
| Отправить в работу | Готовы сохранённые данные задания, БЛЦБ, состав/расчёты, непустое сообщение и рабочий профиль |
| В корзину | Актуальная карточка без несохранённых правок, есть автор |

Во время несовместимой операции соответствующие действия недоступны. При
записи отметки «Учитывать» само рабочее пространство не отключается: строка,
галочка, фокус и прокрутка остаются прежними; недоступны отдельные команды.

## Осмысленные следующие шаги

Готовый ручной результат остаётся доступным для просмотра/копирования даже
когда формирование нового недоступно. Правки пользователя не перестраиваются
автоматически. БЛЦБ не требуется для результата письма, но нужен для цеха.
Вкладка результата позволяет обычный ручной ввод. При пустом результате
причина недоступности формирования видна также в прежней строке состояния
24 px нейтральным текстом, без сдвига документа и без объявления ошибки.

Кнопка просмотра сообщения цеха доступна и при неполных данных: показывает
причину и прежний переход к реквизитам/проекту/спецификациям. Пустое исправленное
сообщение отключает передачу; редактор/«Сбросить» позволяют восстановить его.
Если не задан только путь цеха, действие передачи по-прежнему открывает
настройки хранилища. Выбор конкретных файлов и сетевой доступ проверяются
во время подготовки, без постоянного сканирования папок ради IsEnabled.

В форме проекта сохранение уже созданной заготовки после сбоя БД остаётся
доступным для повтора. Повтор использует тот же ID/файл; обычная отмена такой
подготовки недоступна с объяснением. Неизвестный исход записи по-прежнему
требует явного F5. «Выбрать папку хранения…» сразу открывает «Хранилище».

## Реализация

`WorkflowViewModel.Actions.cs` содержит обычные проверки загруженного состояния
и причины. Формирование результата использует одну проверку и для доступности,
и перед выполнением. Отправка использует прежний CuttingTaskPreview.
Кнопки и четыре пункта меню связаны с теми же свойствами; Toolkit-команды
получают CanExecute. Закрытые/устаревшие пункты сохраняют прежние проверки
контекста; открытое меню обновляет доступность, если состояние изменилось.
Проверки самих действий и условной записи остаются обязательными.

Подсказки включены и на недоступных элементах через ShowOnDisabled. Изменения
полей, карточки, профиля, занятости, состава и принятия спецификаций обновляют
состояния через существующие уведомления, без перезагрузки карточки/списка.
Геттеры не читают БД, файлы или сеть. Новых опросов, таймеров, внешних подписок,
зависимостей, настроек и полей БД нет. JSON12/MDB2/IPC1 прежние.

## Проверка

`WorkflowActionAvailabilityTests`: обе темы 1180/1366×768, путь пустая заявка →
проект → принятая спецификация → правки → БЛЦБ → готовое задание. Проверяются
одинаковая доступность меню/кнопок, подсказки, сохранность ручного текста,
отсутствие записи при вводе новой заявки и защита от повторного сброса формы.
Отдельно — исключённые позиции/варианты, профиль, положительная толщина,
отсутствующий путь, чтение доступности при заблокированном файле БД,
повтор после сбоя без второй заготовки. Прежние UI-тесты текста цеха используют
доступный просмотр причины вместо нажатия недоступной передачи.

Итог: 604 Release pass / 6 штатных skip, 7 новых случаев, Python 9 pass;
Debug/Release/win-x64 cross-build без предупреждений/ошибок. Прежние проверки
включения проекта подтверждают неизменность строк, фокуса и прокрутки при
временной недоступности отдельных действий.
Свидетельства — `.local/action-availability/`. Headless Linux и cross-build
Windows не заменяют проверку настоящего Windows UI/буфера/SMB.
