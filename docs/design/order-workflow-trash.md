# Корзина заявок Workflow

24.10.2026. Локальная реализация корзины и, по следующему запросу пользователя,
удаления из неё одной выбранной заявки или всех показанных заявок. Только
Journal Next, без коммитов/PR/релиза; прежний Journal не затрагивается.

## Поведение

- В заголовке карточки «В корзину…», рядом со списком — «Корзина (N)».
- Подтверждение показывает неизменяемый номер, заказчика, число проектов и
  спецификаций. Начальный фокус на «Отмена»; Esc закрывает без записи.
- До подтверждения нет изменений. После подтверждения заявка исчезает из
  рабочего списка/поиска, но остаётся целиком в данных.
- Корзина — отдельное окно со списком, временем и сотрудником удаления,
  обновлением/F5, «Восстановить», «Удалить выбранную…» и «Очистить корзину…».
  Восстановление возвращает тот же ID/номер.
- Удаление навсегда требует отдельного модального подтверждения с номерами,
  заказчиками и количеством заявок/проектов/спецификаций. Начальный фокус —
  «Отмена», Esc/крестик закрывают без записи. Только явная кнопка удаления
  удаляет данные; восстановить их из корзины после этого нельзя.
- В пустой корзине удаление/очистка/восстановление недоступны. Отложенный ответ
  таблицы с уже удалённой выбранной строкой не включает команды обратно.
- Автоочистки и срока хранения на этом этапе нет.
  Глобальную настройку 30/60/90 дней прежнего продукта не переносим автоматически.

Папки/CAM/HTML/PDF/архивные снимки не удаляются, не переносятся и не
переименовываются. Корзина не проверяет File.Exists и доступность сетевых
папок. При внешнем удалении/недоступности файлов восстановление записи
сохраняет прежние ссылки; файлы автоматически не воссоздаются.

## Данные

Поля WorkflowOrder, введённые в схеме 7 и сохраняемые в текущей схеме 8:

| Поле | Значение |
| --- | --- |
| DeletedAt | UTC-время перемещения; null — активная заявка |
| DeletedBy | EmployeeId удалившего; null вместе с DeletedAt |
| CreatedById | Неизменяемый автор создания, отдельно от текущего ответственного |
| Version | Увеличивается на один при перемещении/восстановлении |
| UpdatedAt / Events | Время и событие операции с действительным ActorId |

IsDeleted вычисляется по DeletedAt и не хранится вторым независимым флагом.
Восстановление очищает DeletedAt/DeletedBy, а события удаления/восстановления
остаются в истории. ID, ReferenceNumber, внутренний Number, CreatedAt,
заказчик/БЛЦБ/сотрудники, позиции/варианты/текущий выбор, версии спецификаций,
снимки тарифов/формула/суммы и ссылки на принятые отчёты сохраняются.

Номера из корзины участвуют в резервировании новых номеров. Восстановление
не создаёт новую заявку и не пересчитывает её. Станки и прочие справочники
ссылающейся заявки по-прежнему считаются используемыми, включая все версии.
При окончательном удалении запись заявки со всеми вложенными позициями,
проектами, версиями расчётов и событиями убирается из workspace. Общие
справочники сотрудников/заказчиков/станков/цен не очищаются. Схема остаётся 8,
новых таблиц, полей и миграции для этого действия нет.

Фильтр рабочего списка исключает IsDeleted во всех поисках. Корзина показывает
только удалённые записи. Она не подменяет производственное «В работе/Готово»
или будущий архив завершённых заявок.

## Окончательное удаление одной или всех заявок

Подтверждение фиксирует список OrderId/Version, а не будущий результат запроса
«всё в корзине». Перед записью проверяется весь список: записи существуют,
версии совпадают, каждая заявка остаётся в корзине и не содержит незавершённого
Rename. Только после всех проверок одна атомарная запись JSON удаляет весь
подтверждённый набор. Чужое восстановление/правка/удаление любой строки отклоняет
всю операцию. Новые заявки, попавшие в корзину после открытия подтверждения,
остаются; изменения других заявок не блокируют очистку старого набора.
Повторный запрос уже удалённых ID не считается новой успешной записью.

Несохранённый черновик удаляемой заявки в этом экземпляре блокирует удаление.
После успешного удаления связанные кэши карточек/писем убираются из сеанса,
чтобы заявка не возвращалась из кэша или данных обновления. Черновики/письма
других заявок и незавершённая новая заявка сохраняются.

Ошибка или неподтверждённый исход оставляют диалог открытым с объяснением.
Повтор удаления и остальные изменения корзины заблокированы до явного
обновления/F5. Не происходит ни автоматического повтора записи, ни очистки
списка по предположению об успехе. Синхронизация файловой системы не нужна:
никаких проверок существования, переноса или удаления рабочих файлов нет.

При чужом окончательном удалении открытая карточка с несохранённым вводом
или письмом сохраняет локальный снимок с пометкой «Удалена · локальный черновик».
Его можно снова открыть из журнала, включая неактивную карточку. Запись в
исчезнувшую заявку недоступна, автоматического восстановления записи нет.
Снимок не добавляется в workspace и не становится общей заявкой. Нужный
текст можно скопировать; явная «Отмена правок» убирает локальный черновик.
Если после удаления заявки станок также удалён из справочника, это не мешает
просмотру старого снимка: используется сохранённое имя расчёта. Такие снимки защищают
от перезапуска для обновления до явного решения пользователя.

## Конкурентная работа и черновики

Подтверждение хранит исходный OrderId/Version. Любая чужая правка после
его открытия отклоняет запись; номер/состав не перечитываются автоматически
ради удаления новой версии. Восстановление также проверяет исходную версию
строки корзины. Повторный равный результат с актуальной версией — no-op,
устаревшие попытки требуют явного обновления. Автоповторов записи нет.

Редактирование удалённой заявки блокируется и в командах домена, и в
WriteOrderAsync. Для восстановления есть явный allowTrashed; он не отменяет
проверок домена при изменении параметров/проектов. Корзина не допускает
тихой записи в удалённую заявку по старому снимку.

Собственное перемещение требует сначала сохранить или отменить текущие
правки/подготовку. Неактивные черновики других заявок не отбрасываются.
Чужое перемещение, обнаруженное при чтении корзины, сохраняет открытый
черновик и показывает состояние карточки. После восстановления старый
черновик не получает новую версию CAS автоматически: пользователь видит
предупреждение и может явно «Отменить правки и обновить».

Если заготовка CAM уже создана, отмена карточки не теряет её: нужно
восстановить заявку и сохранить подготовленный проект. Ручной текст письма
сохраняется в памяти сеанса; его сохранение при рестарте прежним механизмом
не превращается в новое общее поле БД. Пустой результат не помечается устаревшим.

## Миграция и авторство

Версии 1–6 переходят в 7 с резервной копией исходного файла. Старые заявки
остаются активными, данные/цвета/номера/версии/пути/расчёты не переписываются.
CreatedById для прежних записей заполняется только из первого достоверного
события «Создана заявка» с существующим сотрудником. При отсутствии основания
автор остаётся неизвестным; ответственный/редактор/удаливший не подставляются.
У новых заявок CreatedById задаётся сразу при создании. Поэтому полоска
автора не меняет владельца при добавлении событий корзины.

## Следующий общий Access-адаптер

Физический адаптер пока не реализован. В проекте общей схемы —
orders.deleted_at/deleted_by и неизменяемый created_by. Перемещение и
восстановление записываются в одной транзакции с проверкой row/content version
и аудитом; неизвестный commit проверяется по command_id без автоматической
повторной операции. Обычные чтения/записи проверяют deleted_at IS NULL,
восстановление — отдельную ожидаемую версию удалённой записи.

Корзина читается порциями по индексу deleted_at/registration_no, без загрузки
всех спецификаций/отчётов и без обхода файлов. Архив завершённых заявок,
сроки и автоочистка — отдельные будущие решения. Явная безвозвратная очистка
реализована только в локальном JSON; для Access нужны условная проверка
всего набора и удаление связанных записей в одной транзакции. Локальный
JSON-прототип не является проверкой Jet/SMB.
