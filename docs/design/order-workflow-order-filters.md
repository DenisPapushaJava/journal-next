# Фильтры списка заявок

02.11.2026 отбор заявок за месяц: в существующем календаре кнопка
«Весь месяц» применяет показанный месяц целиком. Навигация по месяцам/годам
не меняет отбор до нажатия; Esc сохраняет прежний день/месяц. Кнопка периода
и сводка показывают, например, «Октябрь 2026», при повторном открытии выделены
все дни выбранного месяца. Клик по отдельному дню (включая первое число
того же месяца), Сегодня и Все даты явно выходят из месячного режима.
Основная панель не получает дополнительных кнопок/строк.

Отбор по локальной дате создания заявки, вместе с поиском и быстрыми
фильтрами; прежний порядок строк сохраняется. Месяц и дата применяются
атомарно одним событием, одна отменяемая загрузка через прежний debounce.
MDB получает прежние From/Until: начало месяца включительно, начало
следующего — исключительно, границы переводятся в UTC. SQL уже использует
created_at>=? AND created_at<?, без Month/Year по столбцу, до TOP/COUNT/seek.
Схема/IPC/индексы не меняются; весь журнал ради месяца не загружается.
Локальный JSON фильтруется в памяти без нового I/O. Открытые карточки,
черновики и ручные тексты сохраняются по прежним правилам. Сброс быстрых
условий не меняет месяц/поиск; смена периода закрывает устаревшее ПКМ даже
при совпавшем первом числе. Только локально в Next без публикации,
основной Journal и живые данные не менять. Контракт —
docs/design/order-workflow-period.md.

02.11.2026 быстрый сброс: справа от «Фильтры · N» добавлен компактный
крестик 24×24 DIP, видимый только при активных условиях. Та же команда
ClearQuickOrderFilters, без открытия Flyout и подтверждений; дата/поиск/
карточка/черновики сохраняются. Фокус возвращается к кнопке фильтров, а не
остаётся на исчезнувшем крестике. Обе темы, без изменений БД/настроек/релиза.

02.11.2026 фильтры заявок: компактная кнопка «Фильтры · N» справа от счётчика
над таблицей. Flyout: «Мои заявки», передача в цех (Все / Ещё не переданы /
В работе), «С гибкой», «С фаской» и сброс только этих условий. Кнопка выделена
при активных условиях, tooltip перечисляет их. Без отдельной постоянной
панели/новой вкладки. При пустой выдаче — понятная причина и сброс фильтров;
открытая карточка/черновики сохраняются. «Показать в списке» у карточки вне
выдачи отдельно снимает дату/поиск/все фильтры для возврата открытой заявки.

Дата создания заявки (локальный день), поиск и фильтры объединяются через AND.
Поиск больше не переключает на «Все даты», включая полный номер заявки;
«Все даты» снимает только период, очистка поиска — только текст. Условия
сохраняются при выборе другого дня, F5 и автообновлении; в новый сеанс и
после подключения другой БД — без дополнительных фильтров. В профиль/БД
условия не записываются. Мои — TechnologistId текущего сотрудника, не автор
и не фамилия; при смене сотрудника пересчитываются. Без профиля включение
недоступно; уже активное «Мои» не расширяет выдачу до всех при потере профиля.
В работе — сохранённая отметка заявки, включая изменившуюся после передачи.
Операции — та же ActiveSpecifications, что для бейджей: включённые позиции,
текущие неудалённые варианты и прежние расчёты без проекта. Обе операции
могут быть на разных проектах; отсутствие отчёта не угадывает отметку.

WorkflowOrderFilter — общий критерий по сохранённым данным. Необязательный
Filter в WorkflowReadQuery: старый запрос без него означает все. Для MDB
условия в COUNT и SELECT до TOP/курсора: параметризованный ID ответственного,
EXISTS отметки передачи/сохранённых операций с проверкой включения/выбранного
проекта/корзины, без размножения строк и N+1. Уже есть индекс ответственного;
DDL/новых таблиц/индексов нет. Условия входят в идентичность страницы и
фонового снимка; смена отменяет старое чтение/курсор прежним механизмом.
RetainIds сохраняют открытую карточку, но не обходят фильтр списка/счётчика.
Корзина от быстрых фильтров основного списка независима.

При общем прогоне выявлена зависимость ранее добавленной проекции бейджей
от графического backend через static Geometry.Parse. В WorkflowOrderRow
теперь только строковые пути; геометрия создаётся в визуальном компоненте.
Проверка проекции стала обычным Fact без запуска Avalonia. Форматы
JSON15/MDB5/IPC1/релизные пути прежние; основной Journal и живые данные не
изменять. Работа только локально в Next, без commit/push/PR/релиза.
