# Journal Next

Десктопная программа для технологов: заявка → проекты раскроя → спецификации → расчёт.
Рабочее имя интерфейса можно менять независимо от технического ID приложения.

**[Установщик для Windows](https://github.com/DenisPapushaJava/journal-next/releases)**

Первый выпуск — `2026.1.0-alpha.1`. Установщик `JournalNext-…-win-x64-OfflineSetup.exe`
содержит .NET Runtime x64/x86 и модуль чтения MDB. После установки обновления
доступны через колокольчик или «Настройки → Программа»; для альфа-выпусков
включено получение тестовых версий.

В alpha.2 добавлены создание/подключение общей MDB через «Настройки → Хранилище».
Состав обновления — [описание изменений](docs/release-notes.md). Публикация
проходит Windows-проверки; совместную работу на реальной SMB-папке проверяют отдельно.
Из прежней MDB импортируются только цены, без изменения исходной базы.
Принятые HTML/PDF сохраняются рядом с проектами в служебной подпапке.

## Разработка

MDB создаётся на Windows, с таблицами, связями, индексами и собственным ID.
Новая база содержит только штатные станки. Тестовые заявки JSON автоматически
не переносятся. Общий файл подключается на каждом ПК, личный профиль/списки
остаются в локальном preferences.json. Недоступный путь не создаёт базу заново.
Подробности: [контракт MDB](docs/design/order-workflow-access.md).

Локальная модель после 25.10.2026 хранит один актуальный расчёт и последний
принятый отчёт на спецификацию, без ленты истории и цепочек редакций.
JSON 1–10 обновляется до 11 с резервной копией исходника; рабочие файлы
не удаляются. Варианты проектов и защита одновременного сохранения остаются.

В локальной версии расчёт открывается прямо под выбранным проектом.
Две вкладки: «Проекты» и «Письмо»; загрузка спецификаций — из папок проектов,
цены настраиваются в общем каталоге. Принцип дальнейших доработок — понятный
рабочий путь без дублирования экранов и лишних переходов.

В VS Code откройте корневую папку `journal-next`. В разделе «Запуск и отладка»
выберите «Journal Next: запуск и отладка»: **F5** сначала собирает Debug, затем
запускает программу с отладчиком; **Ctrl+F5** запускает без отладчика.
**Ctrl+Shift+B** выполняет ту же сборку отдельно. Конфигурации находятся
в `.vscode/launch.json` и `.vscode/tasks.json`; Linux использует SDK из `~/.dotnet`.

```sh
dotnet restore Journal.Next.slnx --locked-mode
dotnet build Journal.Next.slnx -c Release --no-restore
dotnet test tests/Jornal.Workflow.Tests -c Release --no-build --no-restore
dotnet run --project src/Jornal.Workflow.Desktop
```

Прежний Journal развивается в собственном репозитории. Здесь свой origin,
пакет `DenisPapusha.JournalWorkflow`, профиль `JournalWorkflow`, канал
`workflow-win-x64` и теги `workflow-v…`. Совпадение имён библиотек совместимости
не означает общий профиль или автоматическое обновление другой программы.

CI — один обязательный Windows job. Release — отдельная проверка упаковки,
чистой установки, установленного Jet-хоста, обновления до реального приложения,
восстановления текста через Windows UI Automation и сохранности данных.
Публикуются ровно установщик, полный пакет обновления, feed и SHA256SUMS.

Подробности сценариев: [разработка](docs/order-workflow-development.md),
[принятые требования](docs/order-workflow-feedback.md). Файлы рабочих БД,
пользовательских настроек и отчётов в Git не включаются.
