Постоянное правило для MDB (уточнено 26.10.2026): учитывать подтверждённый
сбой передачи дробных Decimal/Numeric-параметров в связке .NET/OLE DB/Jet.
Новые decimal-поля и записи проводить через существующие mapping/планы
WorkflowMdbStatements с проверкой точности; не возвращать прямую передачу
дробных параметров без нативной проверки. При похожем 80040E07 сначала
локализовать SQL/столбец/тип/порядок параметров, не объявлять причиной запятую
или повреждение БД. После изменения SQL/числовых полей/драйвера/runtime нужны
точные Windows Jet x86 проверки, включая ru-RU; Linux их не заменяет.
Не применять этот обход автоматически к другим провайдерам или продуктам.
Подробное постоянное правило: docs/design/order-workflow-access.md,
раздел «Дробные числа: правило для последующих изменений».
